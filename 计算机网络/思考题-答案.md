# 计算机网络 · 第 1 章 思考题 参考答案

> 对应 `思考题.docx`（第 1 章，共 2 题，均为填表题；原卷只有场景与空表）。
> 填表口径：**发送端自上而下逐层封装，接收端自下而上逐层解封装**，每层只读写自己那层的首部。
> 类比题（第 2 题）没有唯一标准答案，下表给一种自洽的映射；考试按老师课堂口径，能讲清"每层各管什么"即可。

## 1. 王伟点奶茶 / 视频通话 / 查看配送

### 1.1 填表（主线取"给父母打视频电话"）

三件事里只有视频通话是"王伟 ↔ 父母"端到端直连，所以表格用它当主线；点奶茶、查看配送是王伟与平台服务器之间的交互，写法同理，见 1.2。

| 步骤 | 王伟（发送端）做了什么？ | 对应网络层次 | 父母（接收端）做了什么？ |
|---|---|---|---|
| 1 | 打开微信点"视频通话"，摄像头/麦克风采集音视频，App 编码成数据 | **应用层**（相当于写信人写好信） | 微信弹出呼叫，接听，App 解码并播放画面与声音 |
| 2 | 数据切成段，段首部写源端口/目的端口，标明"这是微信的流量" | **运输层**（相当于信封上的"收件人姓名/工号"） | 按端口把数据交给微信进程，而不是系统里其他程序 |
| 3 | 每个分组加源 IP（王伟手机）和目的 IP（父母手机或中转服务器） | **网络层**（相当于"省市区+街道"地址） | 核对目的 IP 是否为自己，确认没送错主机，再去掉这层首部 |
| 4 | 封装成帧，写下一跳的 MAC 地址（家里的路由器/基站） | **数据链路层**（相当于快递的"转运单"） | 所在网络的路由器/基站按 MAC 把帧转发给父母手机 |
| 5 | 变成 0/1 比特流，经 Wi‑Fi 无线电波或光纤发出去 | **物理层**（相当于货车和公路） | 天线/网卡把电信号还原成比特流，交给上一层 |

### 1.2 三件事分别落在哪一层

| 行为 | 应用层做什么 | 运输层 | 为什么这么选 |
|---|---|---|---|
| 点奶茶 | 外卖 App 与平台服务器交互（HTTPS，HTTP over TLS） | TCP | 订单、支付不能丢也不能重复，宁可慢一点 |
| 视频通话 | 微信音视频协议（RTP 一类） | 多为 UDP | 容忍少量丢包，要低时延；丢了不重传，避免越等越卡 |
| 查看配送位置 | App 轮询或长连接（HTTPS / WebSocket） | TCP | 报文小但要求送达、按序 |

**要点**

- 分层的好处：骑手不需要知道订单内容，只看地址；路由器不需要知道传的是视频还是订单，只看 IP。各层只处理自己那部分首部。
- 封装顺序：应用数据 → 加运输层首部（段）→ 加网络层首部（分组）→ 加链路层首部/尾部（帧）→ 比特流；接收端反过来拆。
- "点奶茶"的接收方是平台服务器而不是父母，所以它不填在第一张表的"父母"列里。

## 2. 天津 → 上海：邮政系统与快递系统对照

### 2.1 发件地环节

| 邮政系统 | 快递系统 | 对照解释 |
|---|---|---|
| **天津（发件地）**：天津的邮局/邮筒，信件从这里进入邮政网 | 天津的快递网点/分拨中心，包裹从这里进入快递网 | **源主机所在的局域网/接入网**：数据从主机进入互联网的入口 |
| **写信人**：写信、装信封、写清收件人地址与邮编、贴邮票 | 寄件人下单、填电子面单（寄/收件人、电话、地址、物品） | **应用层**：发送方应用进程产生报文，并按协议填好地址等字段 |
| **收件规则**：信封格式、邮政编码、资费、禁寄品规定 | 面单字段、实名制、保价与时效规则 | **应用层协议**：双方约定的报文格式与语义（如 HTTP 的请求行与头字段） |
| **邮局收发邮件**：收寄、盖邮戳、称重、登记 | 快递员揽收、扫码入库、打印运单 | **传输层**：把应用数据切成分段并编号，用端口区分进程，提供端到端服务 |
| **邮局分拣邮件**：按目的地城市/邮路分拣装袋 | 分拨中心按目的地分拣、装车 | **网络层**：按目的 IP 查路由表选下一跳，路由器逐跳转发 |
| **运输部门之间的约定**：邮政与铁路/航空/公路部门的交接单、时限、责任划分 | 快递公司与航空/干线承运商的交接规范、扫描节点 | **数据链路层**：相邻节点间的帧格式、差错检测、介质访问规则 |
| **邮局运输部门**：火车/汽车/飞机实际运送邮袋 | 干线车辆/货运航班实际运输包裹 | **物理层**：比特流在光纤、无线电等介质上传输 |

### 2.2 收件地环节

| 邮政系统 | 快递系统 | 对照解释 |
|---|---|---|
| **上海（收件地）**：上海邮政局投递部 | 上海快递网点/末端驿站 | **目的主机所在的网络**：数据从互联网进入目的主机所在网段 |
| **通信者之间约定**：寄信人与收信人都按信封格式书写/识读 | 寄件人与收件人都按面单理解信息 | **应用层协议**：双方使用同一协议，才能解析对方的报文 |
| **收信人**：收信人本人签收 | 收件人本人或代收点签收 | **目的应用进程**：数据最终交给的那个进程（由端口定位） |
| **拆信、阅读信件**：拆信封、读信 | 拆包裹、验货 | **解封装**：逐层去掉首部，把数据交给应用层解析 |
| **分发邮件**：投递员按地址投到信箱/上门 | 快递员按地址送到门口/驿站 | **数据链路层（最后一跳）**：同一网段内按 MAC 地址交付到目的主机 |
| **分拣信件**：上海邮局按街道/门牌分拣 | 上海分拨中心按片区/站点分拣 | **网络层（入方向）**：按目的地址决定投递路径，逐跳靠近目的主机 |
| **运输邮件**：市内邮车运送 | 末端配送车辆运送 | **物理层**：最后一跳的比特流传输 |

### 2.3 一句话总结

邮政/快递系统能把一封信从天津送到上海，靠的是"写信人—邮局—分拣—运输—投递—收信人"这套分工；计算机网络能把一个分组从源主机送到目的主机，靠的是"应用层—运输层—网络层—链路层—物理层"这套分工。两者都是**分层 + 逐层封装/解封装 + 每层只守自己的规则**，区别只是计算机网络把"分拣"交给路由器、把"运输"交给链路和介质，并且全部自动化。

> 口径提醒：类比题的对应关系可以有不同的合理划法（例如把"邮局"整体看作运输层、把"分拣中心"看作路由器的选路），只要同一套映射前后一致、能解释"为什么要分层"即可。
