#### 选项详解（逐项，含干扰项）

**1. 答案 C `pwd`** — print working directory，输出当前目录的绝对路径；Shell 内建，也存在 `/bin/pwd`。
- A `mkdir`：建目录，不显示任何路径。
- B `ls`：列目录内容，默认只给名字、不给当前目录的完整路径。
- D `top`：动态看进程与负载，与目录无关。

**2. 答案 C** — 640 = `rw- r-- ---`：所有者 6=rw-、组 4=r--、其他 0=---。
- A 描述的是 764（`rwx rw- r--`）。
- B 描述的是 461（`r-- rw- --x`）。
- D 描述的是 742（`rwx r-- -w-`）。

**3. 答案 D `free -h`** — 以人类可读单位显示内存与 swap 使用。
- A `df -h`：看**文件系统（磁盘）**空间，不是内存。
- B `dh -f`：`dh` 不是系统命令（dpkg 构建工具里的 `dh_*` 与此无关），`-f` 也无所指。
- C `free -ah`：`-a` 不是 `free` 的选项（procps-ng 只有 `-b -k -m -g -h -c -l -s -t -w -v` 等），这条命令直接报错。

**4. 答案 B `:wq`** — write and quit。
- A `:q`：只退出；缓冲区有未保存修改会被拒绝（E37）。
- C `:q!`：强制退出，**丢弃**修改。
- D `:w`：只保存不退出。
- 补充：`:x` 与 `ZZ` 也是"有修改才写、然后退出"。

**5. 答案 D `ln -s`**
- A `ln file.txt slink`：默认建**硬链接**，且要求与源在同一文件系统。
- B `ln -h`：`-h` 不是建链接的选项（GNU coreutils 直接报 invalid option；uutils 版则把它当 `--help` 打印用法），总之不会创建软链接。
- C `ln -b`：`-b` 是 `--backup`，给已存在的目标做备份，建的仍是硬链接。
- D 正确：`-s` 建符号链接，可跨文件系统、可指向目录。

**6. 答案 B `cp -r`**
- A `-i`：覆盖前交互询问，不递归。
- C `-f`：强制覆盖（抵消 `-i`），不递归。
- D `-u`：仅当源比目标新才复制（update），不递归。
- 补充：`cp -R` 同 `-r`；`cp -a` 归档模式，递归并保留权限/时间戳/链接。

**7. 答案 C `ls -lS`** — `-S` 按文件大小排序，默认从大到小；`-l` 长格式。
- A `-lt`：按**修改时间**排序（新→旧）。
- B `-lr`：`-r` 反转排序次序，默认情况下就是按名字逆序。
- D `-ld`：`-d` 只列出**目录自身**一条记录、不展开内容，和排序无关。
- 补充：小→大用 `ls -lSr`。

**8. 答案 A `tar -cf`**
- B `-czf`：多了 `-z`，走 gzip 压缩，产出 .tar.gz 而非纯归档。
- C `-xzf`：`-x` 是解压，方向与题干相反。
- D `zip -r backup.tar dir`：`zip` 产出 ZIP 格式，扩展名写成 .tar 也不改格式，不是 tar 归档。

**9. 答案 A `/boot`**
- B `/opt`：可选/第三方软件安装目录。
- C `/usr`：用户程序与只读数据（bin/lib/share）。
- D `/etc`：系统与服务配置文件。
- 补充：`/boot` 内是 vmlinuz、initrd.img、grub 配置。

**10. 答案 A `ldd`** — 打印 ELF 的动态库依赖（本质是设 `LD_TRACE_LOADED_OBJECTS` 后运行程序）。
- B `nm`：列目标文件/可执行文件的**符号表**。
- C `ar`：静态库（.a）打包与管理工具。
- D `strip`：删除符号与调试信息以减小体积。
- 备注：pptx 给的 D 与选项不符，按知识点应为 A。

**11. 答案 B `?`**
- A `*`：匹配任意长度（含 0 个）字符。
- C `[]`：字符集合，匹配其中**一个**字符，如 `[abc]`。
- D `{}`：花括号**展开**（brace expansion），不是路径名通配符，且要求列表里已有具体项。

**12. 答案 B `uptime`** — 当前时间、已运行时长、登录用户数、1/5/15 分钟负载均值。
- A `free`：内存与 swap。
- C `vmstat`：虚拟内存/进程/分页/块 I/O/CPU 汇总，可带间隔采样。
- D `iostat`：CPU 与磁盘 I/O 统计（sysstat 包）。

**13. 答案 C `ping`** — 发 ICMP Echo Request，测可达性与往返时延。
- A `route`：查看/修改内核路由表。
- B `netstat`：连接、监听端口、路由、接口统计。
- D `ifconfig`：查看/配置网络接口（新系统多用 `ip`，但仍在用）。

**14. 答案 B `yy`** — yank 当前整行（`2yy` 两行，`y$` 到行尾）。
- A `y`：是**操作符**，要再跟动作（`yw`、`y$`）才生效，单按无效果。
- C `p`：粘贴到光标之后（`P` 之前）。
- D `pp`：不存在这个命令（有 `dd`，没有 `pp`）。

**15. 答案 A `ssh`** — 加密远程登录/远程执行命令。
- B `scp`：基于 SSH 的文件复制。
- C `sftp`：基于 SSH 的交互式文件传输。
- D `ftp`：明文 FTP，传文件且不加密。

**16. 答案 B `scp`**
- A `ssh`：登录/远程执行，不负责拷文件。
- C `telnet`：明文远程登录（题干注"远程通信"），不传文件。
- D `rsync`：增量同步工具，**功能上也能在服务器间传文件**且更高效；但单选题标准答案取 `scp`，若为多选可算上。

### 四、简答题

**41. C 语言程序的编译过程共分为几个阶段？各阶段工作内容？**

共 **4 个阶段**：

1. **预处理**：处理所有以 `#` 开头的预处理指令和注释（头文件展开、宏替换、条件编译），生成 `.i` 文件。
2. **编译**：对预处理结果做词法、语法、语义分析，检查无误后生成汇编语言程序（`.s`）。
3. **汇编**：把汇编程序翻译为机器指令（二进制目标文件 `.o`），每条汇编语句几乎对应一条机器指令。
4. **链接**：把同一程序的多个目标文件与相关系统库链接，最终生成可执行文件。

**42. Linux 中几种常用特殊目录及其含义（举例）**

以当前工作目录 `/home/can` 为例：

1. `.`：当前工作目录，等同 `/home/can`。
2. `..`：上一层目录，即 `/home`。
3. `-`：前一个工作目录。执行 `cd /etc` 后，`.` 是 `/etc`，`-` 是 `/home/can`（`cd -` 可来回切换）。
4. `~`：当前用户的主目录，即 `/home/can`；`~guest` 表示 guest 的家目录 `/home/guest`。

### 一、选择题（1–8）

| 题号 | 题干要点 | 答案 | 解析 |
|---|---|---|---|
| 1 | 当前脚本文件名 | **B** | `$0`；`$#` 参数个数、`$@` 全部参数数组 |
| 2 | 上一条命令退出状态码 | **C** | `$?`（0 成功，非 0 失败） |

| 4 | 最近一个后台进程 PID | **A** | `$!`；`$$` 当前 Shell PID |
| 5 | 定义 calc_sum 的正确开头 | **A** | `calc_sum() {` |
| 6 | 打印到终端 | **A** | `echo`（`printf` 也能打印，但本题按 echo） |
| 7 | 跳出当前循环 | **A** | `break` |
| 8 | 跳过本次剩余代码进入下一轮 | **B** | `continue` |

#### 选项详解（逐项，含干扰项）

**1. 答案 B `$0`**
- A `@#`、C `@0`：都不是合法变量（原 pptx 原文，照录），展开为空串。
- D `$@`：全部位置参数（加引号时每个参数独立成词）。
- 补充：`$0` 是脚本被调用时的名字；`bash script.sh` 下是 `script.sh`。

**2. 答案 C `$?`** — 上一条命令的退出状态码（管道取最后一个命令），0 成功、非 0 失败。
- A `$#`：位置参数个数。
- B `$!`：最近一个后台进程的 PID。
- D `$@`：全部位置参数。

**3. 答案 C `return`** — 只能用在函数（或 `source` 的脚本）里，返回 0–255 的状态码，调用方用 `$?` 取。
- A `break`：跳出循环。
- B `continue`：进入下一轮循环。
- D `exit`：退出整个脚本/Shell，作用域是整个进程，不是"函数返回"。

**4. 答案 A `$!`** — 最近一个 `&` 后台任务的 PID。
- B `$$`：当前 Shell（脚本）自身的 PID。
- C `$?`：上一条命令的退出状态码。
- D `$*`：全部位置参数拼成一个字符串。

**5. 答案 A `calc_sum() {`**
- B `function calc_sum （`：Bash 的 `function 名字` 形式后面直接接 `{`，要带括号只能成对写成 `()`；这里只有一个全角左括号且未闭合，语法不成立。
- C `def calc_sum(`：Python 语法。
- D `func calc_sum {`：Go 的关键字，Bash 无此写法。

**6. 答案 A `echo`**
- B `cat`：读文件/标准输入并输出内容，不用于打印字符串（`cat <<< "$x"` 算绕路）。
- C `printf`：**也能**打印到终端，格式化能力更强；但本题按"打印字符串或变量"的标准答案取 `echo`。
- D `export`：把变量标记为导出（传给子进程），本身不产生输出。

**7. 答案 A `break`** — 跳出**最内层**循环；`break n` 可跳出 n 层。
- B `continue`：结束本轮，进入下一轮。
- C `exit`：退出整个脚本。
- D `return`：从函数返回，不用于跳出循环。

**8. 答案 B `continue`**
- A `break`：直接结束循环。
- C `exit`：退出脚本。
- D `return`：退出函数。

### 三、简答题 14：`$*` 与 `$@` 的区别

- 不加双引号时二者表现相同，都代表传给脚本的全部参数。
- 加双引号时本质不同：
  - `"$*"`：把所有参数当作**一个整体字符串**，等价 `"$1 $2 $3 ..."`。
  - `"$@"`：把每个参数当作**独立字符串**，等价 `"$1" "$2" "$3" ...`。
- 因此 `for arg in "$@"` 遍历时能正确保留参数内部的空格，是推荐写法。

### 二、简答题 5：什么是系统调用？与库函数有何区别？

- **系统调用**：操作系统内核提供给应用程序的编程接口，应用通过它请求内核服务（文件读写、进程管理等），运行在**内核态**。
- **库函数**：用户态提供的封装函数，内部可能调用一个或多个系统调用。
- **区别**：
  1. 执行环境不同——系统调用在内核态执行，库函数在用户态执行；
  2. 系统调用直接陷入内核、开销较大；库函数更高级、更易用。

## 第 5 讲 进程控制

### 题目与答案（1–9）

| 题号 | 答案 | 说明 |
|---|---|---|
| 1 | **C** | `fork()` 父进程返回子进程 PID；子进程返回 0；失败返回 −1 |
| 2 | **√** | `wait()` 阻塞父进程直到某个子进程退出（并回收僵尸） |
| 3 | **就绪态** | 已获得除 CPU 外的全部资源，等待调度 |
| 4 | **0** | 返回 0 表示当前代码运行在子进程 |
| 5 | **−1** | `fork()` 失败返回 −1 并置 `errno` |
| 6 | **等待态（阻塞态）** | 等待事件（如 I/O 完成），不占 CPU |
| 7 | **运行态、就绪态、等待态** | 三态模型 |
| 8 | **PCB** | 进程控制块（Linux 中为 `task_struct`） |
| 9 | 见下 | 守护进程 |

**1 的选项详解（fork 返回值只有三种情况）**
- A `0`：**子进程**里返回的值，表示"我是子进程"（与第 4 题同一事实）。
- B `−1`：失败返回，同时置 `errno`（`EAGAIN` 资源不足、`ENOMEM` 内存不够等，见第 5 题）。
- C 子进程 PID：**父进程**里返回，父进程靠它区分、`wait`/`kill` 子进程。
- D `1`：不会出现。成功时父进程拿到的是子进程 PID（子进程 PID 不会是 1，1 通常归 init/systemd），也不存在"返回 1 表示成功"的约定。
- 补充：`fork` 之后父子进程都从 `fork` 返回处继续执行，**返回值不同是区分两者的唯一手段**；返回两次、执行一次。

**9. 什么是守护进程（daemon）？简述创建步骤。**

守护进程：在**后台运行、脱离终端会话、长期驻留**、独立于用户会话的进程。

创建步骤：

1. `fork()` 创建子进程后，**父进程退出**（让子进程不被当成会话组长）；
2. 子进程调用 **`setsid()`** 创建新会话并成为会话首进程；
3. `chdir("/")` 把工作目录改为根目录（避免占住可卸载的文件系统）；
4. `umask(0)` 设置文件权限掩码；
5. 关闭标准输入/输出/错误（0、1、2），重定向到 `/dev/null`。

**4. 简述 SIGKILL(9) 与 SIGTERM(15) 的区别**

- **SIGTERM(15)**：`kill` 默认发送的**优雅终止**信号。进程可以捕获、处理或忽略，从而在退出前释放资源、保存状态。
- **SIGKILL(9)**：**强制终止**信号。进程不能捕获、处理或忽略，由内核直接杀死。用于进程无响应或拒绝处理 SIGTERM 时。

## 第 7 章 进程间通信

### 一、选择题（1–2）

| 题号 | 答案 | 解析 |
|---|---|---|
| 1 | **D** | `shmat()` 附加共享内存；`shmget()` 创建、`shmdt()` 分离、`shmctl()` 控制 |
| 2 | **B** | `msgsnd()` 发送；`msgrcv()` 接收、`msgget()` 建队列、`msgctl()` 控制 |

#### 选项详解（逐项，含干扰项）

**1. 答案 D `shmat()`** — shared memory attach，把共享内存段映射进本进程地址空间，返回可用指针。
- A `shmctl()`：控制操作，`IPC_STAT` 查属性、`IPC_SET` 改属性、`IPC_RMID` 删除段。
- B `shmget()`：创建或获取共享内存段，返回 shmid。
- C `shmdt()`：detach，把段从本进程地址空间分离。
- 典型顺序：`shmget` → `shmat` → 读写 → `shmdt` → `shmctl(IPC_RMID)`。

**2. 答案 B `msgsnd()`** — 发送消息；队列满且非阻塞时返回 -1、`errno=EAGAIN`。
- A `msgget()`：创建/获取消息队列，返回 msqid。
- C `msgrcv()`：接收消息（可按 mtype 选取）。
- D `msgctl()`：控制队列（`IPC_STAT`/`IPC_SET`/`IPC_RMID`）。

### 三、简答题 7：无名管道（Pipe）的特点及使用限制

**特点**

- 半双工通信：数据单向流动，一端读、另一端写。
- 存在于内存中：没有实体文件，随进程结束而销毁。

**使用限制**

- 只能用于具有亲缘关系（父子、兄弟进程）的进程间通信，因为无名管道的文件描述符只能通过 `fork()` 继承传递。

### 四、编程题 8：统计目录下 .c 文件个数

```bash
#!/bin/bash
# 检查参数是否为空
if [ -z "$1" ]; then
    echo "请提供目录路径"
    exit 1
fi
# 检查目录是否存在
if [ ! -d "$1" ]; then
    echo "目录不存在"
    exit 1
fi
# 统计 .c 文件个数
# -maxdepth 1：只看该目录本层，不进入子目录
# -type f：只要普通文件，排除名字恰好以 .c 结尾的目录
# -name "*.c"：匹配 .c 后缀
count=$(find "$1" -maxdepth 1 -type f -name "*.c" | wc -l)
# 格式化输出
echo "目录$1下共有$count个C语言源文件"
```

> `wc` 是 word/line/byte count，统计行数、单词数、字节数：
> `-l` 数行、`-w` 数单词（以空白分隔）、`-c` 数字节。
> 这里 `find` 每找到一个文件就输出一行路径，所以行数就是文件个数。
> 不用 `ls "$1"/*.c | wc -l`：零匹配时 `ls` 会报错，同名目录也会被当成 `ls` 的参数列出来。

### 五、分析题 10：多线程程序找错并改对

**原程序**

```c
#include <stdio.h>
#include <pthread.h>
#include <stdlib.h>
int shared = 0;               // 共享变量
void* add(void* arg) {
    for (int i = 0; i < 1000; i++) {
        shared++;             // 修改共享变量
    }
    return NULL;
}
int main() {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, add, NULL);
    pthread_create(&t2, NULL, add, NULL);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    printf("shared = %d\n", shared);
    return 0;
}
```

**（1）功能与缺陷**

- 功能：创建两个线程并发执行 `add`，各自对共享变量 `shared` 自增 1000 次，最终打印 `shared`，用于演示多线程并发访问共享变量。
- 缺陷：两个线程同时修改 `shared` 且**未加互斥锁保护**，存在**数据竞争（竞态条件）**，`shared++` 非原子（读-改-写三步），最终结果**可能小于 2000 且不确定**。

**（2）修改后的完整代码**

```c
#include <stdio.h>
#include <pthread.h>
#include <stdlib.h>

int shared = 0;                    // 定义共享变量
pthread_mutex_t mutex;             // 定义互斥锁

void* add(void* arg) {
    for (int i = 0; i < 1000; i++) {
        pthread_mutex_lock(&mutex);        // 加锁，保护共享变量
        shared++;
        pthread_mutex_unlock(&mutex);      // 解锁
    }
    return NULL;
}

int main() {
    pthread_t t1, t2;
    pthread_mutex_init(&mutex, NULL);      // 初始化互斥锁
    pthread_create(&t1, NULL, add, NULL);
    pthread_create(&t2, NULL, add, NULL);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    pthread_mutex_destroy(&mutex);         // 销毁互斥锁
    printf("shared = %d\n", shared);
    return 0;
}
```

编译：`gcc -o t t.c -lpthread`，运行结果恒为 `shared = 2000`。
